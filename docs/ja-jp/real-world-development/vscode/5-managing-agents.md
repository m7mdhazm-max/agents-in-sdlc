GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を受け入れるか元に戻すかを選び、エディターを離れずに追加のプロンプトで作業を調整したり広げたりできます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイルの編集をレビューして受け入れる。
- セッションの途中でエージェントに指示を追加し、ハイ コントラスト モードにライト モードのトグルを加える。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者向けに、ライト モードの切り替えも追加してほしいとのことです。新しい会話を始めるのではなく、既存のセッションに指示を追加して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが行う各ステップ (調べたファイル、実行したコマンド、提案した編集) を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
    - 変更を受け入れるには **Keep** を選択します。
    - 変更を元に戻してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開いて、このセッションでエージェントが変更した作業ファイル全体を確認することもできます。

> [!NOTE]
> ツール呼び出しで (ターミナル コマンドの実行などの) 許可が求められた場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードができたので、同じ会話でライト モードのトグルも追加します。同じ Chat セッションを続けるため、エージェントは前の作業、変更したコンポーネント、スタイルの方針、local storage のパターンなどのコンテキストを保持しています。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を調べ、ライト モードの追加を提案します。
3. 前の作業と同様に、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (たとえば、トグル UI を望まない方法でリファクタリングしようとする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、補足のプロンプトを送ります。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも早く作業できます。追加プロンプトで変更を依頼します (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正します (「3 つ目のトグルを作らず、ライト モードを既存の設定パネルに追加する」)、または範囲を広げます (「両方のトグルにキーボード ショートカットも追加する」)。

## 作業ファイル全体をレビューする

作業をコミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルを一覧で確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタム エージェントが示したアクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で進行中のセッションを監視し、各ファイル編集を確認して、変更を受け入れるか元に戻すかを選びました。また、コンテキストを失わずに追加プロンプトを送り、作業範囲を広げました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視した。
- 個々のファイル編集を受け入れるか元に戻した。
- 追加プロンプトで進行中のセッションに指示を出した。
